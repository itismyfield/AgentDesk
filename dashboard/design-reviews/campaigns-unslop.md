# 캠페인 디자인 확인

대상은 `/campaigns`의 기존 캠페인·서버 캠페인, 선택 상세·수정, 생성·정의 편집, 관계 보기, 오류·빈 상태다. foundation PR #7564 위에 쌓으며 서버·API·WS 코드는 변경하지 않는다.

## 기준에서 추출한 원칙

- [Linear 검색](https://linear.app/docs/search): 제목과 식별자를 분리하고 검색·필터를 작업 목록 앞에서 찾게 한다.
- [Vercel 대시보드 개편](https://vercel.com/blog/dashboard-redesign): 제목과 주 행동 → 선택한 캠페인의 운영 정보 → 작업 탐색 → 선택 상세의 위계를 둔다.
- [Grafana Node Exporter](https://grafana.com/grafana/dashboards/1860-node-exporter-full/): 요약은 짧게, 전체 데이터는 일정한 행과 구분선으로 비교한다.
- 홈 PR #7562의 중립 표면·얇은 경계·작은 모서리·제한된 상태 강조를 이어간다. 레퍼런스의 픽셀·브랜드를 복제하지 않는다. 위 항목은 화면에서 추출해 이 화면에 적용한 설계 판단이다.

## 정보 구조와 모바일 동작

실데이터에는 진행 작업 16개가 있어 필터와 그룹 목록을 여러 화면 아래로 밀었다. 검색·필터를 먼저 배치하고 진행 요약은 기본 3개, 390px에서는 1개를 보인다. `진행 중 N개 모두 보기`로 모두 열 수 있고 상태별 목록도 남긴다. 막힌 작업이 있으면 요약 맨 앞에서 드러낸다. 긴 설명은 펼침 영역으로 옮긴다. 기대효과가 없는 카드의 반복 빈 문장은 생략하며 기록된 내용은 표시한다.

행은 제목·식별자를 먼저 읽고 상태·단계·라운드·담당을 비교한다. 제목은 줄바꿈하고 모바일에서도 담당을 보인다. PC 선택 상세 옆에서는 긴 단계명이 제목을 밀지 않도록 메타데이터 열을 고정했다. 원문 단계·담당은 title과 상세에 남긴다. 상세·편집 폼은 모바일 한 열, PC 두 열로 표시한다.

서버 캠페인의 별도 선택 목록은 펼침 영역에 두고 선택기의 모든 항목도 유지한다. 준비·실행·중단·재개·재시도 명령과 거절 사유를 보존했다. 생성 폼의 수용조건 ID·설명·검증 종류에 보이는 라벨을 붙였다. 버튼·필드·링크·펼침·체크박스 라벨은 44px 높이를 사용한다.

주 구조·행·상세·폼은 JSX Tailwind utility로 옮겼다. 남은 기존 그래프/표현 CSS는 components layer에 두어 utility가 우선하도록 했다. 기존 필터·탭·보기·편집·실행 기능을 삭제하지 않았다. 캠페인에는 별도 Modal/Drawer가 없고 상세와 폼은 인라인이다.

## 실화면 확인 범위

캡처 루트는 `output/playwright/unslop-campaigns/`다. 변경 전은 `before/campaigns-{390,1440}-{light,dark}.png`, 변경 후는 `final/{390,1440}-{light,dark}-*.png`다.

- 기존 캠페인 12상태: 개요, 설명, 필터, 검색 결과 없음, 펼친 작업 목록, 작업 상세, 수정 폼, 수정 동작, 선택 관계, 전체 그룹 관계, 완료 목록, 진행 전체 목록.
- 서버 캠페인 17상태: 준비, 펼친 선택 목록, 작업 상세, 정의 편집, 빈 생성 폼, 작업/수용조건 입력, 선행 관계 입력, 실행 실패, 리뷰 대기, main 이후 검증 대기, 중단 확인 중, 중단 완료, 재시도 준비, 실패 후 진행 불가, 재시도 없이 재개 가능, 빈 작업, 빈 캠페인.
- 추가 2상태: 막힘 우선 요약, 긴 담당자명 상세(browser fixture).
- 오류 3상태: 최초 조회 실패, 이전 스냅샷 보존, 정의 저장 거절.
- 모든 상태를 390/1440 × light/dark로 확인한다. 기존 캠페인과 긴 제목·단계는 실행 서버 실데이터다. 서버 상태·빈 화면·오류·폼 저장 거절은 browser fixture이며 기존 `serverCampaignsFixtures.ts`와 API 계약을 사용한다.
- API 쓰기를 브라우저에서 가로채 서버에 전달하지 않는다. 저장 거절 재현만 4번의 mock POST를 허용하고 fixture가 400 응답을 반환한다. 메시지·병합·배포를 수행하지 않는다.

## 확인과 수정 루프

직접 본 이미지에서 진행 카드로 인한 필터 지연, PC 상세를 열었을 때 제목이 한 글자 열로 눌리는 현상, 수용조건 필드의 라벨 부재, 모바일에서 사라지던 담당, 라이트 상태 텍스트 대비와 다크 그래프의 흰 조작 배경을 고친 후 같은 상태를 다시 찍었다. 가로 넘침·조작 크기와 선택 상세 옆 제목 120px 이상 검사도 실행한다.

- `npm --prefix dashboard run build` 성공.
- 캠페인 관련 단위 테스트 120개 통과.
- 모바일 경로 가로 넘침 smoke: 1개 통과, PC 전용 1개 skip (`PLAYWRIGHT_PORT=5277`).
- Playwright CLI 기본 34상태 × 4조합 = 136 PNG와 진행 2/3개 fixture 12장(PC 기본·모바일 기본/펼침), 합계 148 PNG. 캡처와 스크립트는 review archive에 포함한다.
- 44px 조작·가로 넘침·선택 상세 옆 작업 제목 최소 폭 검사를 통과했다. foundation `4c299336f0`의 최신 테마 토큰을 통합한 최종 5개 CLI 스크립트가 모두 통과했다. 모바일 진행 2/3개일 때도 나머지 요약을 펼칠 수 있고 마지막 카드로 진입함을 검증했다. 다크 그래프 조작의 실제 배경도 검사했다.
