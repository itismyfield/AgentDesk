# 음성·통계·루틴 디자인 확인

공통 PR #7564 위에서 `/voice`, `/stats`, `/routines`를 다룬다. 머지·배포하지 않는다.

## 기준과 정보 구조

[Linear 검색](https://linear.app/docs/search)의 목록·식별자 정렬, [Vercel 대시보드](https://vercel.com/blog/dashboard-redesign)의 제목/주 행동 구분, [Grafana](https://grafana.com/grafana/dashboards/1860-node-exporter-full/)의 요약→상세 흐름을 추출했다. 브랜드·픽셀은 복제하지 않는다.

- 음성: 제목/사용 안내 → 대화와 작업 상태 → 오류 → 모드와 마이크. 발화자·응답·담당 상태를 구분하고 긴 내용은 줄바꿈한다. 390px 마이크80px, PC96px, 보조 조작44px이다. 녹음·STT·conductor·TTS 계약과 폴링은 유지한다. 직접 처리하는 API 오류는 중복 토스트를 억제해 마이크를 덮지 않게 하고, 긴 오류는 독립 스크롤 영역에 표시한다.
- 통계: 제목/기간 → 핵심 수치(모바일2열, PC4열) → 계정 → 사용량 차트 → 비교 목록 → 비용 내역/스킬·순위. 중첩 상자·대형 수치를 줄이고 제목/보조 문구/숫자를 구분했다. 숫자 계산·데이터 순서·필터는 보존한다. 영수증은 흰 종이·바코드 장식 대신 테마에 맞는 비용 명세로 정리했다. 긴 모델/에이전트/계정명은 줄바꿈한다. 통계 전용 CSS-in-JS281줄을 제거하고 Tailwind로 옮겼다.
- 루틴: 승인된 홈과 같은 요약·일정 행을 전용 화면에서도 사용한다. 전체/활성/일시정지 필터, 다음 실행순 정렬, 상세·최근 실행·결과·원본 JSON을 유지한다. 중복 바닥 여백을 줄였다.

통계 실제 조회 실패 시 수치가 영구 `…`로 남던 문제를 발견했다. 요청이 끝난 뒤 데이터가 없으면 `—`와 `데이터 확인 불가`로 표시하고, 실제0과 구분한다. 오류 회귀 E2E를 추가했다.

## 검증 자료

`output/playwright/unslop-operations/before/`는 변경 전 실페이지16장(운영4장은 별도 #7570의 baseline으로도 사용). `after/`와 `verify.js`, `stats-states.js`, `extra-states.js`가 최종 화면/재현 자료다. 모든 상태는390×844·1440×1000, light/dark로 확인한다.

- 음성: 초기, 수동/핸즈프리, 녹음, 긴 요청·완료 응답, 마이크 권한 거부, STT실패, 작업 전달 실패.
- 루틴: 실목록, 필터 빈 상태, 상세/하단. fixture에서 등록0/목록 오류/실행0/실행 오류/긴 루틴명·script_ref·오류·결과·원본 JSON 펼침.
- 통계: 정상·긴 모델/에이전트/스킬/계정명, 90일 전환, 하단, 비용 명세 펼침, 등록0/통계 오류/계정 오류. 실제 서버 집계는 검증 시점 요청 실패가 발생했으므로 정상·빈·오류 집계는 기존 E2E API 계약의 browser fixture로 구분해 확인한다.
- 음성 녹음 장치와 `/api/voice/**` 쓰기는 브라우저에서 가로챈다. 실제 마이크·에이전트 작업/설정 변경은 수행하지 않는다. 비용·계정 전환 쓰기를 실행하지 않는다.
- production build 성공. 모델·루틴·영수증 단위18개 통과. stats/routines E2E7개 통과, viewport별1개 정상skip. 독립 리뷰에서 기존 데이터 계산·음성 흐름·상세 동작 보존을 확인했다.

실화면의 정렬·간격·잘림·긴 데이터·빈 상태·44px 조작을 계측하고 이미지를 직접 확인했다. 원본 JSON 펼침 버튼, 통계 실패의 영구 로딩, 중복 음성 오류 토스트를 수정하고 같은 상태를 재촬영한다. 최종 캡처 수와 최종 재검증은 아래에 추가한다.
