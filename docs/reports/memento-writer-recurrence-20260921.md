# Memento writer recurrence prevention

Historical initial-phase notes. The reviewed follow-up changes and release status
are in [memento-writer-followup-20260921.md](memento-writer-followup-20260921.md);
its generation, failure recovery, and hook behavior supersede this initial design.

Scope: AgentDesk client/writer only. Base `20fdea82f1`; isolated branch
`fix/memento-writer-novelty-20260921`. No deployment, live MCP call, database
operation, fragment cleanup, provider reconfiguration, or existing-session
intervention was performed.

## Findings, in investigation order

1. **Raw turn capture:** `memory_lifecycle.rs::plan_turn_memory_tasks` does not
   schedule Memento raw capture. `MementoBackend::capture` is already inert.
   The existing regression test covers long transcripts that formerly produced
   truncated episode fragments. This was not a currently active writer.
2. **Reflect and summary:** `MementoBackend::reflect` is already inert, although
   legacy session-end scheduling still exists. A separate active writer remained:
   `policies/kanban-rules.js` terminal callbacks call `retrospectives.rs`, which
   formerly mirrored every generated card summary to `remember`. Deduplication
   only covered `(card_id, dispatch_id, terminal_status)`. A new dispatch, elapsed
   duration, or review count produced another episode without new knowledge.
   This automatic mirror is now disabled; the local retrospective is retained.
3. **Routines:** the maintenance job invokes `memory_consolidate`, not `remember`.
   The migrated hygiene script also contains an error-to-procedure remember
   instruction followed by deletion instructions. That re-save instruction is
   now replaced with preserving/reporting the original error for review. Neither
   job/script was run. Routine retries retain the original prompt; a memory write completed
   before a later turn failure can be requested again on the next attempt.
4. **Retry and direct writes:** the old remember cache lasted five minutes, was
   lost on restart, and checked before the remote call without an atomic claim.
   Its key omitted fact/status metadata and endpoint identity. The transport
   retried errors matching broad session/401 text. Model-owned MCP calls bypass
   this Rust client entirely because provider config points directly upstream.

## Changes

- `memento_writer_guard.rs`: durable SHA-256 receipts, process-safe file locks,
  confirmed/pending state, no TTL. Receipts retain no fact text or credentials.
  Identity includes endpoint, credential identity, and all argument fields except
  source and importance; content whitespace follows existing client normalization.
- `memento.rs`: guarded remember transport; no automatic replay after an
  ambiguous write. Session initialization/connect failures and HTTP 401 release
  the claim because no write was accepted. Session errors invalidate the cached
  session even when replay is disabled. Confirmed duplicates skip the remote call.
- `memento_throttle.rs`: removes the superseded five-minute remember cache.
- `memento_writer_hook.rs`, hook relay, and `mcp_config.rs`: managed Claude/Codex remember and
  reflect calls receive a local PreToolUse gate for confirmed-success duplicates.
  PostToolUse confirms only the originating session/tool invocation with positive
  success evidence; unknown/cancelled invocations remain retryable. Amend and
  unrelated tools retain existing behavior. This runs independently of relay
  availability; provider config and live sessions were not changed.
- `retrospectives.rs`: automatic semantic-memory mirror disabled, reported as
  `skipped_no_new_knowledge`; local audit data still generated by the existing path.
- `memento-hygiene.sh`: removes the old-error-to-new-procedure rewrite instruction;
  those originals are preserved and reported as review candidates.
- Tests cover confirmed duplicates, whitespace/source/importance variants,
  concurrent processes/calls, restart, ambiguous failures, new family facts,
  changed fact metadata/scope, and amend bypass.

## Operational boundaries

Deploy through the separate runtime-ops procedure, protecting active sessions.
This change is not installed in the running service or existing hook executable.
Keep the client and hook receipt directories with the runtime state; clearing
receipts, changing credentials/endpoints, or using another runtime root resets
that identity's local history. Receipts are additive client state, not Memento DB
records. No existing fragments are seeded or modified.

An ambiguous pending client write must be reconciled with a read-only lookup
before recovery. It is never reported as a successful write and does not block
different new content. Do not blindly remove a pending client receipt and replay.
Hook invocations with no confirmed success remain retryable: provider cancellation
and permission rejection before dispatch cannot be distinguished reliably from
an unknown upstream outcome. Therefore concurrent first calls and unknown-result
retries are protected by the Rust client, but not by the model hook alone.

Hook identity comes from the managed provider MCP configuration, not the separate
memory backend config. If that identity cannot be established, the hook leaves
the ordinary provider flow unchanged to avoid blocking another store's new fact.

Coverage is managed Claude/Codex hooks plus AgentDesk's Rust remember client.
Unmanaged callers, other provider hooks, and differently named MCP connectors
are outside this gate. Client and provider-hook receipts are separate, so they
do not deduplicate across those two transports. The rule is conservative payload
identity, not a semantic similarity classifier: novel wording, case IDs, keyword
ordering, or other semantic fields remain writable. This preserves new personal
and family facts instead of guessing that similar facts are interchangeable.

## Validation

All regression tests use temporary receipt directories and loopback mock MCP
servers; no operational memory server or database is involved.

```sh
python3 scripts/build_token.py -- env -u AGENTDESK_ROOT_DIR \
  CARGO_TARGET_DIR="$PWD/target" CARGO_BUILD_JOBS=2 \
  cargo test --lib -- \
  services::memory::memento:: \
  services::memory::memento_writer_guard:: \
  services::retrospectives::tests \
  services::claude_tui::memento_writer_hook:: \
  memento_writer_hook_identity \
  memento_turn_plan_never_schedules_raw_capture \
  --test-threads=1
bash -n scripts/launchd-migrated/memento-hygiene.sh
git diff --check
```

**Final result: 47 passed, 0 failed (1.41 seconds after compilation).**
Duplicate normalized/source/importance-only writes dispatch exactly once across
backend recreation; changed family facts, assertions, scopes, cases, and outcomes
dispatch normally. Amend passes the hook gate. Concurrent client writes dispatch
once, ambiguous client results are not replayed, and confirmed model writes are
denied on the next invocation. Corrupt hook confirmations recover atomically.

Modified Rust files also pass `rustfmt --edition 2024 --check`.
The full crate test build emits existing unrelated warning debt; no broad CI or
live end-to-end deployment test is claimed. The final targeted output is retained
in `target/memento-verified-tests.log` in this worktree.

Independent review identified and drove corrections for definite no-send retries,
expired-session cache invalidation, actual provider MCP identity, cancellation
safety, and atomic confirmation publication. Final review found no blocking issue.
