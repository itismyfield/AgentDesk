# #7819 시험의 고정 sleep·전역 상태 주입 — 실측과 조각 계획

대상: [#7819](https://github.com/itismyfield/AgentDesk/issues/7819) (댓글로 옮겨 온 병렬 멈춤 관측과 #7818 항목 포함).
측정 기준: `406da315a7344c1d0116a5bb1d1bbe9f75c2f20f` (origin/main, 2026-11-16).
이 문서는 읽기 전용 조사 결과와 조각 계획이다. 코드·시험을 바꾸지 않았고 cargo 빌드도 하지 않았다.
수치는 모두 아래 §1의 명령 출력에서 왔다. 추정치에는 "추정"이라고 적었다.

상태 차트: 해당 없음. 사유: 시험의 대기 방식과 시험 전용 전역 상태 주입을 바꾸는 리팩터이고, 운영 상태 전이를 만들거나 바꾸지 않는다.

## 0. 결론

1. **PG 묶음이 끝나지 않았다.** #8052는 fixture 2개(dispatch·canonical identity)만 실패로 바꿨다.
   PG가 없으면 조용히 통과하는 지점이 아직 **20파일 34곳**(base 없음 22곳 + 연결 실패 12곳)이고, 이 fixture를 쓰는 시험은 98개다.
   11-10 사용자 결정의 범위(시험 코드만, 조각 4개 안쪽)에 그대로 들어가므로 **첫 조각(P1)**으로 한다.
2. **병렬 멈춤의 원인 후보를 코드에서 찾았다.** 공유 env lock(E)과 `provider_hosting::TEST_CONFIG_LOCK`(C)을 잡는 순서가 시험마다 다르다(E→C와 C→E, ABBA).
   댓글의 두 멈춤 시험은 모두 E를 쥔 뒤 C를 기다린다. C는 lock_holder 감시 대상이 아니어서 E를 쥔 시험만 이름이 찍혔다. 이 내용은 실행으로 확인하지 않았고 H1 조각에서 재현한다.
3. **git 실행기는 env lock과 무관하다.** 시험이 git 관련 환경변수를 바꾸거나 PATH에 가짜 git을 끼우는 곳이 0이다. git 주입은 env lock 제거에 도움이 되지 않으므로 DoD에서 "주입 안 함(사유)"로 바꾸자고 제안한다(§10 결정 1).
4. **runtime_root가 env lock의 대부분이다.** env lock 취득 1,449곳 가운데 987곳(293파일)은 `AGENTDESK_ROOT_DIR` 하나를 바꾸려고 잠근다.
   그중 876곳은 #7651 소유(407곳)이거나, 주입할 자리가 #8192가 옮기는 SharedData/EngineRuntime인 discord 코드(469곳)다. 그래서 지금 할 수 있는 것은 비-discord 85곳(R1·R2)이다.
5. **지역 polling 헬퍼 65개가 49+6개 파일에 흩어져 있다.** `test_support::wait`에 deadline polling 함수 하나를 더해 모은다(W0). 규칙 8의 예외이므로 코디네이터 승인이 필요하다.
6. 조각 수: 전체 **51조각**. 지금 할 수 있는 조각은 21개이고, **30개는 뒤로** 미룬다(#7651 14, #8192 6, #7583 5, 그 밖의 레인과 재산정 5).

## 1. 측정 방법

규칙 8(시험용 census 금지)에 따라 계수 스크립트는 저장소에 넣지 않았다. 스크립트와 원자료는 레인 산출물 폴더(`~/.adk/release/lane-runs/hl-20260925/i7819/measure/`)에 있다.

- **시험 전용 코드 판정**: `scripts/ci/rust_test_sources.py`의 `unbounded_waits`(`scripts/ci/rust_test_sources.py:692`) 규칙을 그대로 쓴다.
  cfg(test)로만 닿는 파일 전체, `#![cfg(test)]` 블록, `#[cfg(test)]`·`#[test]`·`#[tokio::test]` 뒤의 항목이 시험 코드다. 파일 목록은 `lib_inventory`의 cfg 사슬에 `tests/`를 더한다.
- **sleep 호출**: 위 구간 안의 `sleep(`·`sleep_until(` 호출이다(`fn` 정의와 메서드 호출은 뺀다). 경로로 `std::thread`/`tokio::time`을 가르고, 경로가 없으면 파일의 `use`로 정한다.
  지역 래퍼 2개(`src/services/tui_o/writer/resume_tests.rs:182`, `src/server/routes/health_api/db_deadline_tests/amplification_profile_tests.rs:283`)의 호출 19곳은 각각 tokio·std 쪽으로 넣었다.
  - `poll`: `loop`/`while`/`for … in` 본문 안의 sleep(polling 간격).
  - `virtual`: 시계를 멈춘 파일(`start_paused = true`, `.start_paused(true)`, `time::pause()`)의 tokio sleep. 판정 단위가 파일이라, 같은 파일 안에서 실제 시간으로 도는 시험의 sleep도 여기 들어간다(상한).
  - `fixed`: 나머지(직선 고정 대기). DoD의 "고정 sleep"은 이 묶음을 중심으로 본다.
- **전역 진입점**: 같은 시험 구간 판정에서 시험 밖의 호출을 생산 호출로 셌다. `config::runtime_root()`, discord `runtime_store`의 `agentdesk_root/runtime_root/worktrees_root`, `git_command()`·`GitCommand::new()`, `platform::tmux::*` 함수 호출이 대상이다.
- **env lock 취득**: `rg`로 셌다. `acquire_shared_test_env_lock()`, 낱말 경계가 있는 `shared_test_env_lock()`, `set_agentdesk_root_for_test(`, 스스로 잠그는 `TestEnvVarGuard::set_path/set_value/set/remove(`가 대상이다. 정의 파일(`src/config.rs`, `src/config/test_env.rs`)은 뺐다.
  시험 정책 문서의 "980줄"은 원시 문자열 수라서 이 값과 정의가 다르다.
- **PG skip**: `postgres_test_database_url_base()` 호출 54곳의 문맥을 하나씩 읽어 `?`·`else { return }`·`is_none()` 반환을 골랐다. 연결 실패 skip은 `eprintln!("skipping …")` 뒤의 `return None`이다.
  소비 시험은 그 fixture를 `let Some(x) = … .await else {` 로 받는 곳이다. 분류는 `python3 scripts/ci/pg_test_classifier.py classify --json-out …`(rc=0, PG 시험 3,291개, 문제 0)과 대조했다.
- **레인 소유**: §6의 경로 패턴으로 묶었다. 맞는 패턴이 없으면 `free`다.

## 4. 주입 방식

### 4.1 시간

- 시계를 멈춰도 되는 곳은 생산자가 같은 tokio 런타임의 타이머로만 움직이는 경우다. 이때 `start_paused`와 `advance`를 쓴다. 기존 예는 `src/services/discord/commands/control/clear_persist_failure_tests.rs:235`(멈춘 런타임 `:76`에서 600초 대기)다.
- 생산자가 외부 프로세스·PG·파일시스템·std 스레드에 걸려 있으면 실제 시간을 쓴다. W0의 deadline polling을 쓰고, 상한은 `WAIT_CAP`을 기본으로 한다.
- 이벤트를 받을 수 있으면 sleep을 지우고 channel·`Notify`·barrier로 기다린다(`recv_within`·`await_within`). 생산 코드에 신호를 새로 내야 할 때는 인자로 주입한다. 시험 전용 hook static은 만들지 않는다(규칙 3·11).
- 파일 mtime 차이를 만들려는 sleep은 `File::set_modified`로 시각을 직접 정한다.
- 바꿀 수 없는 sleep은 §9 사유 목록에 남긴다(DoD 1).

### 4.2 runtime_root

- **인자 주입**으로 한다. 시험이 부르는 leaf 함수에 `root: &Path`를 받는 형태를 두고, 기존 무인자 함수는 `runtime_root()`을 읽어 넘기는 얇은 래퍼로 남긴다.
  생산 경로의 동작은 같고, 생산 코드에 `cfg(test)` 분기를 더하지 않는다. 시험은 tempdir을 넘기고 env 가드와 E를 지운다.
- thread-local·task-local override는 쓰지 않는다. 규칙 11(새 test-hook static 금지)에 걸리고, `spawn`·`spawn_blocking`·std 스레드로 넘어가면 기본 root로 조용히 돌아간다. 실패하지 않고 다른 경로에 쓰게 된다.
- discord 엔진 쪽은 SharedData를 거쳐 root를 읽는 시험이 대부분이다(예: `queue_io/idle_queue_tests.rs`가 `make_shared_data_for_tests` 뒤 mailbox 저장으로 root를 읽음). 주입할 자리는 #8192 P0의 EngineRuntime이다.
  그래서 R-discord는 #8192 P0 착지 뒤에 한다. 그때 `src/services/discord/runtime_store.rs:16`의 시험 분기도 지운다(생산 코드의 시험 분기가 줄어든다).

### 4.3 tmux

- 동작을 보는 시험은 `InteractiveSessionHost` 가짜를 인자로 받는다. tmux CLI 출력 파싱처럼 CLI 경계를 보는 시험만 `FakeTmux` 바이너리를 쓰고, 그 경로는 PATH가 아니라 인자로 넘긴다.
- #7583(세션 호스트 공통화)이 1단계를 막 착지했고(406da315a7) 다음 단계가 tmux 실행 경로를 바꾼다. 주입 지점을 그 단계와 맞춘 뒤 한다(T 조각은 뒤로).

### 4.4 git

시험이 git 환경변수나 가짜 git을 쓰는 곳이 0이고, 시험은 tempdir 저장소에서 실제 git을 돌린다. 이것은 실제 외부 경계다.
주입해도 지울 env lock이 없으므로 git 실행기 주입은 하지 않는다. DoD 문구를 고치자고 제안한다(§10 결정 1).

### 4.5 잠금 순서(H1)

C는 E 안쪽에서만 잡는다(E→C→P). `TEST_CONFIG_LOCK`을 직접 잠그던 24곳은 접근 함수 하나로 바꾼다. 그 함수는 lock_holder에 C 슬롯을 등록하고, E를 잡을 때 C를 이미 쥐고 있으면 즉시 panic한다.
P에 쓰는 기존 검사(`src/db/postgres.rs:714`)와 같은 모양이다. C→E 순서인 시험(`herdr_settings_tests.rs` 7개, `effort_settings_tests.rs`)은 E를 먼저 잡게 고친다.

## 8. 리뷰 집중 항목

### 8.1 가상 시계가 실제 시간 경계를 덮는 곳

- **멈춘 시계의 자동 전진**: tokio는 시계가 멈춘 상태에서 런타임이 할 일이 없으면 다음 타이머로 시계를 넘긴다. PG 소켓·자식 프로세스 파이프·`spawn_blocking`을 기다리는 동안에도 넘긴다. 그러면 `timeout`과 deadline이 곧바로 끝나 거짓 실패가 나거나, "N초 동안 안 일어남" 단언이 실제로는 아무것도 기다리지 않고 통과한다.
  해당 후보는 fixed 가운데 PG 27·process 108·mtime 10, poll 가운데 PG 잠금 대기 polling(지역 헬퍼 18개, 15파일)이다. 이곳은 `start_paused`를 쓰지 않고 실제 시간 deadline polling을 쓴다.
- **std 시간을 읽는 생산자**: `std::thread::sleep`·`std::time::Instant`·`SystemTime`은 tokio 시계를 따르지 않는다. 예: git 실행기의 `POLL_INTERVAL`과 `DEFAULT_GIT_TIMEOUT`(`src/services/git/runner.rs:10`–`:11`).
  std::thread sleep 370곳(fixed 172)은 가상 시계로 바꿀 수 없다. 이벤트 동기화나 실제 시간 polling만 가능하다.
- **negative window 73곳**: 생산자가 같은 런타임의 tokio 타이머로 움직일 때만 멈춘 시계 위의 "안 일어남"이 뜻을 가진다. 그렇지 않으면 실제 시간 상한을 두고 그 값을 사유 목록에 남긴다.
- **파일 mtime 10곳**: 가짜 시간은 mtime을 바꾸지 않는다. `File::set_modified`로 바꾼다.

### 8.2 생산 코드에 시험 전용 분기가 넓어지는가

- R1·R2는 인자를 받는 함수와 얇은 래퍼만 더한다. `cfg(test)` 분기도 env 스위치도 더하지 않는다. R-8192 단계에서는 오히려 기존 시험 분기(`runtime_store.rs:16`)를 지운다.
- H1의 접근 함수와 검사는 시험 전용 잠금에 대한 `#[cfg(test)]` 항목이고 생산 경로에는 없다. 다만 규칙 11("새 test-hook static 금지")과 맞닿는다. 새 static은 C를 쥐었는지 기록하는 thread-local 표지 하나이고, P의 선례(`src/db/postgres.rs:714`)와 같다. 리뷰에서 이 점을 판정한다.
- W0는 시험 전용 모듈(`test_support`)에만 더한다. 규칙 8 예외 승인이 필요하다.
- T는 이미 있는 `InteractiveSessionHost`를 인자로 받는다. 새 trait나 env 스위치를 만들지 않는다.

## 9. 남은 sleep 사유 목록(DoD 1) 운영

- 새 census 스크립트나 CI 목록 파일을 만들지 않는다(규칙 8, #8131 충돌 파일을 늘리지 않음). 각 S 조각 PR이 이 문서의 아래 표에 남는 sleep을 `파일` + `함수 이름` + 사유 코드로 더한다. 줄 번호는 바뀌므로 쓰지 않는다.
- 사유 코드: `R-PROC`(외부 프로세스의 실제 시간), `R-PG`(PG 서버 쪽 진행), `R-FS`(파일시스템 감시·mtime을 직접 정할 수 없음), `R-THREAD`(std 스레드 생산자에 신호를 넣을 수 없음), `R-MEASURE`(시간 자체를 재는 시험, 예: `amplification_profile_tests.rs`의 `sleep_until`), `R-HELPER`(공용 대기 헬퍼 내부, 예: `src/test_support/wait.rs:15`의 1ms 간격).
