# 사용자 기능 지도의 tmux·Herdr 동작

기준 소스는 `origin/main`의 `cd9951d3cac6a4f0b81d02789facabbc6ed2a55d`다. [#8128](https://github.com/itismyfield/AgentDesk/issues/8128)은 각 현행 tmux 사용자 결과를 Herdr에서도 제공할 것을 요구한다. [#8275](https://github.com/itismyfield/AgentDesk/issues/8275)의 11-20 08:44 KST 결정은 #7583과 #8128이 완료된 뒤 tmux 퇴역을 재개한다는 뜻이다. 지금 #8275의 GitHub 상태는 CLOSED/NOT_PLANNED다.

11-20 10:2x KST 사용자 결정 A를 반영했다. 복원 창 자동 정리는 서버가 불변 복원 계보, 복원 이후 활동 이력 없음, 남은 작업 없음을 닫는 시점에 함께 증명하는 창에 한정한다. W1은 격리 환경에서 이 증거를 읽어 확인하는 작업이다. W2에서 필요한 서버 능력이 없거나 증거가 불명확하면 해당 창은 남긴다.

이 표는 [#8123 사용자 기능 지도](user-feature-map.md)에 붙일 호스트 열의 설계다. 기존 11개 `feature_id`와 host/provider/surface/state/qualifiers 키를 사용한다. 한 기능에서 결과가 갈리는 표면·명령은 같은 행 ID 아래 세부 행으로 둔다. `추가 관찰 항목`은 현행 지도에 정확히 대응하는 계약이 없는 경우다. 예를 들어 세션 화면 출력과 턴 본문 전달은 서로 다른 사용자 결과다. 상세 근거와 구현 처방은 [관리 명령·진단](herdr-parity-next-admin.design.md)과 [clear 종료·재시작 정리](herdr-parity-next-lifecycle.design.md)를 참조한다.

**같음**은 명시한 조건에서 코드상 동일한 사용자 계약이다. **다름**은 확인한 사용자 결과 또는 지원 범위의 차이다. 양쪽 실제 실행 증거의 부재는 해당 담당 이슈에 별도로 명시한다. **불가피(사유)**는 사용자에게 보이는 차이와 승인 상태를 함께 적는다. `herdr` 열은 실제 Herdr 실행을 뜻한다. Herdr 설정 부모 아래 tmux로 뜨는 자식은 스레드 행에 따로 적었다. 좌표는 기준 SHA에서 읽는다.

## 한 표로 생성할 계약

현 [수기 정본](user-feature-map.rows.yaml)과 [생성기](../scripts/generate_user_feature_map.py)는 11개 ID와 host별 applicable 조합을 이미 고정한다. 구현 조각은 `validate_rows`(`scripts/generate_user_feature_map.py:96`)에서 각 기존 기능에 위 호스트 열을 매핑하는 선언을 검사하고, `render`(`:375`)가 **같은 기능 표에 tmux 동작·Herdr 동작·판정/담당 열을 출력**하도록 한다. 세부 계약은 같은 ID 아래 배치하며, 실제 host별 근거가 갈리면 현재 `tuple_key`(`:62`)의 provider/surface/state/qualifiers를 인용한다. 기존 ID가 없는 관리·진단·legacy 항목도 같은 표에서 별도 행으로 출력한다. 실행 명세가 아직 없는 행은 행 수준 호스트 계약으로만 표시하고 existing applicable/required 키는 그대로 보존한다. 기존 시나리오별 `covered`는 `generate`(`:337`)의 실제 선언 조합과 필수 assertion 기준으로 계산한다. 그 키나 계약을 제거하도록 ratchet을 조정하지 않는다.

11개 ID 및 부속 행, 양쪽 동작, 판정, 담당, 근거가 표에 있어야 한다. `다름` 행은 담당 이슈를, `불가피` 행은 구체 사유와 사용자 확인 상태를 요구한다. 11-13 승인된 인사말 순서 외에는 승인 완료로 올릴 근거를 추가로 확인한다. 기존 명령의 기능을 표에 추가하는 데 새 운영 명령·스위치는 필요 없다.

- RED는 현재 재생성된 기능 지도에서 호스트 열과 차이가 있는 세부 행을 찾을 수 없거나, fixture의 미등록 ID·호스트 한쪽 누락·다름에 담당 이슈 누락·불가피 사유/승인 상태 누락이 유효하게 처리되는 경우다.
- GREEN은 동일 기능 ID와 scope의 한 생성 표에 양쪽 동작과 판정이 나타나고, 위 누락 fixture 모두 검사 오류를 받는 경우다. 기존 applicable/required 조합, coverage, scenario qualifier가 그대로인지 검증한다. 생성물은 `python3 scripts/generate_user_feature_map.py --write --base-ref origin/main`에서 기록하고 `--check`와 CI의 User feature map generation contract(`scripts/ci-script-checks.sh:596,605`)로 검사한다.
- 원인 제거 뮤턴트는 필수 host 열 검사나 render join을 제거하고 대응 시험이 RED임을 확인한 뒤 복원 SHA를 대조한다. 이 레그에서 실행할 검사는 현행 coverage 선언 검사와 문서 행 대조다. E-50/E-51의 4/23은 명세 연결 숫자다. 양쪽 실행은 #8120에서 별도로 head·실행 수·assertion·실제 host의 증거를 모은다.
- 행 4 상태 차트는 **해당 없음(관측 계약과 문서 생성만 바뀌어 세션 전이가 없음)**이다.
- M의 생성 계약은 지금 착수할 수 있다. 현재 판정의 기준은 위 SHA다. 구현 조각별 증거가 확인되면 최종 판정을 갱신한다. 생성 표는 일반 중지, 걸린 턴 해제, 수동 lease 해제를 각각 표시한다. 현재 generator·정본·검사 입력 목록으로 추산한 변경은 prod 1개(`scripts/generate_user_feature_map.py`)와 그 시험, 수기 YAML/생성물이다. 원시 순 코드 증가는 +60~120줄(검사/정규화 +30~55, 렌더 +25~50, 배선 +5~15)로 예상하며 공통 보고서의 실측 보정을 적용한다. #7583 실행 코드와 파일 공유가 없다.
