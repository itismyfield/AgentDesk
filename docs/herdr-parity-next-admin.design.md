- 최신 설계 ref의 소비자 목록 `consumer-slices.tsv`에서 S07a는 `src/server/routes/agents.rs`와 `src/services/agents/turn.rs`, S07b는 `src/services/discord/admin_host_guard.rs`와 `src/services/discord/commands/control/{provider_reset,relaunch,managed_reset}.rs` 및 `src/services/discord/commands/diagnostics/reports.rs`, S07c는 `src/services/discord/commands/{tmux_recreate,tui_passthrough}.rs`와 `src/services/discord/commands/diagnostics/session_details.rs`, S07e는 `src/services/dispatched_sessions/output.rs`다. 같은 파일에 쓰는 D/R2a/R2b/C는 해당 부분 착지 뒤 구현한다. R2c는 R2a의 effect 계약을 소비한다. #8119 S8b1 settings/queue 및 #8118 verified child의 실제 착지 증거를 확인한다.
- D는 기존 capture·cwd·read view를 재사용하고 exact row·노드·endpoint·pane·execution incarnation을 검증하는 read projection을 추가한다. 화면 판정 실패가 이미 있는 fallback을 막지 않게 한다. 한정된 화면도 신뢰할 수 있는 source로 관측됐을 때만 표시하며, agent turn에서는 현재와 같이 전체 텍스트 가림 뒤 끝 부분을 자른다. row guard의 쓰기용 소비자는 별개로 유지한다. R2는 기존 reconcile/termination의 owner·nonce·dispatch fence와 postlude를 소비한다. agent stop에는 holder interrupt만 재사용하며 그 API의 효과에는 close·queue purge가 없다. R2b 재개는 기존 launch·owner queue를 쓴다. 새 내부 코드는 reset/보존 의도를 exact target에 묶고 selector·pending 적용을 확인하는 경계다.
- 첫 효과 전에 기존 exact teardown warrant를 확보한다. admission 뒤 target·token·slot 세대가 바뀌면 새 세대를 종료하지 않는다. close 응답을 확인하지 못했거나 퇴역이 확인되지 않으면 pending과 보존 범위를 그대로 둔다. 관측 실패·ambiguous identity·다른 노드·미배치/unknown은 기존 보존 또는 forwarding 의미를 사용한다.
- Auto queue의 affected row마다 소유/held/active를 검증하고 첫 SQL/물리 효과 직전에 run/custody를 재검증한다. 후처리에서 기존 권한으로 selector/slot을 전이한다. 기존 `auto_queue/runtime.rs:243,269`의 tmux 비동기 순서를 새 Herdr close에 복제하지 않는다. `provider_reset.rs:21,38,58,70`의 기존 tmux 경로는 DB/memory 정리 뒤 bool recreate 결과를 성공에 반영하지 않는다. Herdr에서는 정확 종료와 후처리 확인 뒤 적용으로 응답한다. 기존 tmux 결함은 별도 수리 범위다.
- `agents_crud.rs` 1,500줄, `health/recovery.rs` 5,178줄, `intake_turn.rs` 2,277줄 등 giant에는 호출 교체·블록 이동만 한다.
- 상태 차트는 D에 해당 없음이다. 상태·화면 읽기와 projection만 바뀐다. C는 기존 native 입력 전이를 소비하므로 세션 수명 차트에 해당 없음이다. R2는 [restart 차트](statecharts/index.d/166-session-lifecycle-herdr-restart-b2b.md)의 exact 종료·clear 경쟁·selector 효과를 재사용한다. R2c처럼 호출자 상태의 새 commit 시점이 생기면 구현 전에 같은 세션 수명 모델에 reset intent와 슬롯/receipt 효과 경계를 추가해 검증한다.
- 신규 운영 명령·스위치가 필요한 행은 0개다. 승인된 restart 인사말 순서 예외와 raw tmux 전용 도구는 기능 지도에서 추적한다.
