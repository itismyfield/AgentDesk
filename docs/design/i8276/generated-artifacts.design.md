## 전수표

행 단위는 독립적으로 처분할 수 있는 파일, 생성 블록, 또는 같은 명령·소비자·처분을 공유하는 파일군이다. 파일군은 경로와 파일 수를 병기했다. 처분 단위는 40개다. 같은 경로의 독립 블록은 각 행에 센다. `git ls-files`로 추적 여부를 확인하고 `git grep -ilE 'GENERATED|DO NOT EDIT|autogenerated|@generated'`의 표식, 생성기의 파일 쓰기 경로, lockfile·fixture의 provenance를 대조했다. `D`는 생성물 freshness 검사가 실패한 실행, `C`는 실제 병합 충돌 사례다. `0*`은 조사한 기록에서 해당 행에 귀속한 사례 0건이며 전체 실제 횟수는 미확정이다. 사고별 증거와 집계 범위는 아래에 있다.

S1은 일반 README 수정과 두 레인의 서로 다른 `index.d` 추가가 함께 병합돼도 기본 작업 트리가 깨끗한 상태로 끝나게 한다. CI는 동일한 렌더 계약으로 불변 SHA의 base와 후보를 각각 읽고 두 SHA를 summary와 artifact에 기록한다. 삭제 또는 변경된 행을 요약하고 전체 렌더를 올린다. 로컬 렌더는 링크가 기존과 같은 디렉터리에서 풀리게 하고 CI 요약의 파일 링크는 후보 SHA에 고정한다. 이전 base에 조각이 없으면 기존 마커 블록에서 검증 가능한 비교 입력을 읽거나 기준 부재를 명시한다. 없는 base를 빈 색인으로 치환하지 않는다.

S2는 `TEST_LANE_BASELINE_REF` / `GFP_BASE_SHA`에서 해석한 SHA와 후보를 명시한다. Markdown에서 원문 해시가 빠져도 생성 JSON에는 정확한 원문 해시와 스키마를 둔다. CI는 ID, 적용 조합, 필수 단언, coverage 상태 변화와 기존 승인 삭제를 보고한다. 잘못된 소스는 기존 gate처럼 실패하고, 의도된 유효 변경은 리뷰 가능한 diff로 넘긴다. gate 전체가 생성물 없이 성공으로 끝나지 않게 산출물 존재와 후보 식별자를 검증한다. 시나리오 YAML과 수기 행은 그대로 승인 입력이다.

S3은 일반 후보 PR에서 안전 검사와 diff 생성을 수행하고, 착지 단계에서 보존할 파일을 재생성한 뒤 게시할 트리에서 `--check`를 필수화한다. 실제 순서는 **main SHA 고정 → 합성 병합 → 생성 충돌 구역만 정리 → 재생성 및 패치 검토 → 재생성 포함 최종 후보 SHA 고정 → 해당 후보 검증 → 게시**다. merge queue나 squash에서 base가 이동해 제출한 트리가 검사 트리와 달라지면 새 base로 다시 조립한다. main 검증은 최종 합쳐진 HEAD의 같은 검사를 수행한다. 주간 자동 PR 범위는 새 착지 범위와 일치시키며, 전환 중에는 현재 main의 필수 비교가 활성화될 때까지 보정 경로를 유지한다. 수기 충돌과 모든 생성 오류는 즉시 실패한다. `--check-merge`는 작업 사본에서 검증하고 index는 보존한다. 통과 시에도 base·최종 후보·경로와 변화량을 기록하고 실패 시 `head.diff`를 발행한다.

S4는 07 블록 경계를 기존 `required-gate-wiring` 마커 그대로 식별하고, 두 마커 쌍의 중복·교차와 두 블록 밖의 바이트 변화를 거절한다. 카탈로그의 `scenario_catalog`만 자동 해결할 수 있다. 수기 JSON은 세 입력의 변경 의도를 대조한다. 검토된 단독 삭제는 보존하고, 삭제와 수정이 충돌하거나 병합 도중 승인한 변경이 유실되면 착지를 거절한다. 기존 카탈로그 생성기와 기존 시험을 사용한다.

S5는 감사의 기존 hard/ratchet 결정과 경고를 판정 입구에 유지한다. 동일 스캔으로 YAML·Markdown을 얻고 finding 키와 경로를 정렬해 base/head를 비교한다. 분류가 바뀐 감사 입력은 기존 형식 검사를 타고, 파싱 오류나 base 누락은 명시적으로 실패한다. 경고-only 정책은 그대로 적용한다.

## 실패 한 줄과 DoD 3 입증

유효 입력을 자동 렌더하는 경로와 그 입력을 검증하는 경로를 별도로 시험한다. 각 실패 fixture에서 출력·종료 코드·원인 경로·실행 가능한 복구 명령 1줄을 함께 단언한다. 오래된 바이트만 실패시키던 검사는 재생성 대상 구역에서 최종 트리 비교로 계속 작동한다. 중단하는 산출물은 같은 입력에서 두 번의 동일 바이트, base/head 일치·차이, 잘못된 소스의 실패를 함께 증명한다.

| 부류 | 양성 대조와 음성 대조 | 실패 시 인쇄할 한 줄 |
|---|---|---|
| S1 색인 | 서로 다른 조각 두 개의 동시 추가를 합성 병합하고 두 행과 링크의 base/head 변화가 있는지 확인. 동일 입력의 출력은 동일. 조각 중복 키, 네 열 위반, 깨진 상대 링크, 폐지된 마커 재도입, 수기 README 충돌은 실패. 전환 시험에서는 옛 마커의 누락·중복도 실패. 출력 누락 또는 변조도 게시 검증에서 실패. | `python3 scripts/ci/statechart_index.py --output docs/statecharts/index.generated.md` (신규 출력 옵션, 소스 오류는 오류 위치를 수정하고 재실행) |
| S2 지도 | 현재 `tests.test_generate_user_feature_map`의 tuple/claim/witness/시험 정의·삭제 승인 부정 사례 유지. base 하나와 후보 하나에서 필수 단언 삭제·지원하지 않는 witness·숨긴 tuple을 각각 실패시킨다. source_hash만 달라지는 case는 Markdown 동일·JSON hash diff, covered→gap은 요약에 표시. JSON이 없을 때 깨끗한 clone에서 생성되고 오래된 Markdown은 최종 착지 비교 실패. | `python3 scripts/generate_user_feature_map.py --write --base-ref origin/main` (CI에서는 기록한 base SHA를 인자로 제시) |
| S3 인벤토리·landing | route, worker, env, CLI, top-level purpose 각각에서 소스만 바꾸고 새 행/삭제가 patch에 보여야 한다. stale generated bytes와 누락 파일은 최종 `DRIFT`. 실제 파싱 오류와 새 모듈의 purpose 누락은 일반 PR에서도 실패. 수기 영역 byte 보존·실패 복구·재실행 동일, 선택하지 않은 파일 stage 금지를 검증. | `python3 scripts/landing/regen_after_merge.py --worktree . --artifact-dir target/landing-regen` |
| S4 배선·혼합 JSON | workflow에서 의도된 needs/if 변경을 렌더하고 이후 필수 경로가 같음을 검증. 필요한 job을 제거하면 기존 의미 gate가 실패. YAML 변동은 카탈로그의 hash를 갱신하고 stale hash는 최종 `DRIFT`. 수기 witness 변경·중복 키·카탈로그 밖 충돌·잘못된 마커가 자동 해결되면 시험을 실패시킨다. | 배선은 `python3 scripts/ci/sync-required-gate-wiring.py`, 카탈로그는 `python3 scripts/e2e/generate_continuous_catalog.py --write` |
| S5 감사 | 동일 fixture의 출력 텍스트/hash 동일. 금지 호출 1개를 추가하면 기존 `--check`가 실패하고 YAML/Markdown에 경로가 모두 남는다. 허용되는 감소는 diff에 남고 과거 allowance를 자동 증가시키지 않는다. | `python3 scripts/audit_maintainability.py --format markdown --check` |

기존 비교 경로의 기초 시험 106개가 통과했다. 대상은 `tests.test_statechart_index`, `tests.test_generate_user_feature_map`, `tests.test_landing_regeneration`, `tests.test_list_merge_guard`다. 위 양성·음성 시험은 구현 조각의 인수 조건이다.

## 저장소 밖 코디 변경 목록

- `build_land_simple.sh` 계열의 개별·묶음 조립 호출에서 새 L 대상과 최종 스테이징 목록을 사용한다. 일반 PR freshness와 exact candidate freshness를 구분하고, 검사된 base/head와 최종 게시 tree가 같은지 확인하는 기존 착지 단계에 연결한다.
- `merge_main_regen.sh:17,39,82–91`의 기능 지도 쌍과 README 색인의 별도 갱신을 새 L 등록과 색인 artifact 생성으로 바꾼다. 삭제된 JSON·마커 블록·옛 시험 목록을 상대 브랜치에서 되살리지 않는다.
- `merge_main_regen.sh:40–45,81,105`의 `docs/generated/*` 상대편 채택과 광역 add를 L의 소유 경로·블록만 대상으로 바꾼다. 보존하는 checksum·승인·목록은 각 기존 검사에 맡긴다. 현행 미추적 목록의 legacy 분기는 구버전 브랜치에서만 사용한다.
- `prepush_gates.sh:108,137–147`의 HEAD 일반 검사에서 소스 계약과 diff를 검증하도록 전환하고, 실제 합성 착지 결과의 바이트 비교는 유지한다. `batch_conflicts.sh:15`에서 순수 생성 충돌과 수기/미분류 충돌을 구별해 로그를 남긴다. 단순 `merge-tree` 결과는 재생성 또는 수기 영역 보존의 증거가 되지 않는다.
- `coord-bg` 결과 기록에 DoD 2의 파일별 원인, 시도, 기준 SHA, 패치 위치를 남긴다. 외부 도구 확인은 로컬에서 확인한 스킬 스크립트와 저장소의 착지 설계 문서 기준이며, 코디네이터의 호스트에만 있는 스크립트 본문 및 실행 로그는 이번 조사 자료에 없었다.
