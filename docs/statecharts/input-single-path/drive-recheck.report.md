# Input owner drive liveness

기준은 #8422 m2 `c7ad3ff2e1f550c4a050067d4c0131257bf668a6`이다. 입력 모델군의 [InputDriveRecheck](InputDriveRecheck.tla)는 `InputPath`의 queue/head와 `InputOwnership`의 wake/grant 경계를 한 원본에 투영한다. 기존 cfg의 과거 동작과 뮤턴트 계약은 각각의 원래 명세에 남겨 둔다. 아래 매트릭스는 이번 레그에서 등록한 cfg 전부다.

## TLC

`QueueEventuallyDelivered`는 전달 자격이 풀린 queued 원본이 결국 전달된다는 PROPERTY다. 약한 공정성은 실행 가능한 판정과 초·deadline 진행에만 적용했다. 외부 Wake, 화면 힌트, host readiness 전이에 공정성을 부여하지 않으며, 준비 신호가 올 때까지의 시간을 이 모델이 보장하지 않는다. 각 Before에는 첫 판정이 멈추고 조건만 조용히 풀린 상태가 영속하는 반례가 있다. 기존 deadline이 제때 해제·깨운 경우는 별도 성공 가능한 경로다. After는 동일 조건에서 유일한 drive가 다시 진행하여 전달한다. 초 단위 모델은 실제 런타임의 스케줄링 및 전송 지연을 포함하지 않는다.

| 같은 경계의 cfg | Before | After |
| --- | --- | --- |
| InputDriveRecheckHandoff | RED `QueueEventuallyDelivered` | GREEN |
| InputDriveRecheckNoGrant | RED `QueueEventuallyDelivered` | GREEN |
| InputDriveRecheckRetryWait | RED `QueueEventuallyDelivered` | GREEN |
| InputDriveRecheckHead | RED `QueueEventuallyDelivered` | GREEN |

TLC 1.7.4, 8 cfg, 16 TLC 실행과 cfg별 공정성 검사 8건. Before 4건은 지정 PROPERTY만 실패하고 After 4건은 전부 통과했다. 안전 불변식 `EmptyHasNoWork`, `OneDelivery`, `NoDeliveryBeforeClear`, `TimerBound`는 전체 cfg에서 통과했다. 재현은 저장소 루트에서 아래 명령을 사용한다.

```sh
python3 scripts/ci/statecharts_tlc.py --base c7ad3ff2e1f550c4a050067d4c0131257bf668a6 \
  --jar ~/.cache/tla2tools/tla2tools.jar --jobs 2
```
